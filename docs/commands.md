# Commands and hooks

Five commands operate the corpus. Twelve hooks run around them. The commands are installed into
`<config>/commands/` from templates and are **yours** afterwards: an update never overwrites one you
have edited, and `./raememberit status --commands` shows how far yours have drifted from the shipped
text so you can port what you want.

## The commands

| Command | Run it when | What it does |
|---|---|---|
| `/recall <topic>` | before investigating anything cold — a repo, a ticket, an error, a tool | expands the query into variants, sweeps the catalog and the full session-log history and Claude Code's own auto-memory, follows wikilinks, reports what was found and *when* it was true, and logs the sweep |
| `/learn [fact]` | the moment you are corrected, state a preference, or a fact costs real effort | classifies it, runs `find-similar.py` and records a verdict per candidate, writes through `mem-write.sh` with a tier and optionally a domain, and confirms in one line |
| `/memory-reflect` | end of session, or when the compaction reminder appears | writes or appends the interaction log, routes any missed durable memory through `/learn`, notes skill candidates without writing them |
| `/skill-mine` | when the start-of-session offer appears | reads only the logs newer than `.last-sweep` plus the corrections log, proposes ranked skill candidates at the second recurrence, writes nothing without a per-candidate yes, stamps the watermark |
| `/memory-audit` | monthly | read-only: index integrity, frontmatter, duplicates and contradictions, staleness, documentation drift, the second silo, delivery, retrieval usage and router precision, then the eval — one findings table, no changes |

Under the plugin route the same five are namespaced `/raememberit:<name>`, plus `/raememberit:setup`,
which is the installer as a conversation.

### The three verdict words

`/learn` never writes without answering `find-similar.py`. Two memories may coexist on one topic
only if they answer *different questions*; "it is about a different ticket" is not a different
question. Default to UPDATE: fewer, richer, current memories beat a larger corpus retrieval cannot
disambiguate.

| Verdict | Meaning |
|---|---|
| NOOP | an existing memory already says this — write nothing, say which |
| UPDATE | an existing memory is right but incomplete — edit it in place |
| ADD | genuinely new |
| SUPERSEDE | an existing memory is now wrong — correct it, note what changed and when |

## The write helper

Every memory goes through `<config>/raememberit/engine/mem-write.sh <feedback|project|reference> <slug>`
with the full markdown on stdin; session logs through `mem-write.sh log <topic>`, which dates the file
and appends to an existing log for the same topic that day. It refuses:

| It rejects | Because |
|---|---|
| a `name:` that does not match the filename | the index keys on it; a mismatch points nowhere |
| a `description:` under 20 characters | it *is* the routing signal |
| a missing `metadata.type:` | it decides the tier |
| `scope:` not `global` or `domain` | a typo would silently seat a domain rule in every context |
| `domain:` not kebab-case tokens | a typo would route to nothing, silently |
| `feedback` or `project` without **Why:** / **How to apply:** | a rule without its incident is unarguable later |
| an existing file without `--update` | that is the verdict, enforced |

Then it rebuilds both indexes and exits 3 if the write left a near-duplicate behind.

## The hooks

Generated by `tools/gen-hook-table.sh` from `engine/settings.fragment.json` — never hand-written.
In the setup this was extracted from, a hand-written table documented a hook that existed in no
settings file, and a claim about it flipped three times across three audits because each read the
previous audit's prose instead of the file.

| Event | Matcher | Script | Timeout |
|---|---|---|---|
| `SessionStart` | _(all)_ | `skillmine-nag.sh` | 5s |
| `SessionStart` | _(all)_ | `truncation-tripwire.sh` | 5s |
| `UserPromptSubmit` | _(all)_ | `inject-memory.sh` | 5s |
| `UserPromptSubmit` | _(all)_ | `context-router.sh` | 5s |
| `UserPromptSubmit` | _(all)_ | `correction-nudge.sh` | 5s |
| `PreCompact` | `auto` | `precompact-notice.sh` | 5s |
| `PostCompact` | _(all)_ | `rearm-inject.sh` | 5s |
| `Stop` | _(all)_ | `require-log.sh` | 5s |
| `Stop` | _(all)_ | `learn-nag.sh` | 5s |
| `SessionEnd` | `clear` | `close-log.sh` | 5s |
| `SessionEnd` | `clear` | `rearm-inject.sh` | 5s |
| `SessionEnd` | _(all)_ | `rebuild-index-hook.sh` | 5s |

| Script | What it does |
|---|---|
| `skillmine-nag.sh` | counts logs newer than `.last-sweep`; past the threshold, *offers* a sweep — never runs one |
| `truncation-tripwire.sh` | reports sessions whose index injection the harness truncated, from the artifacts it leaves, and the last rebuild's budget verdict |
| `inject-memory.sh` | injects `MEMORY.md` once per context window, with a preamble naming the corpus path and the write helper |
| `context-router.sh` | scores the prompt against the catalog, the domain index and every installed command's and skill's description; shadow by default |
| `correction-nudge.sh` | a prompt that reads like a correction is logged and answered with one line naming `/learn` |
| `precompact-notice.sh` | before automatic compaction: capture the log and durable memories now |
| `rearm-inject.sh` | after compaction and at session end: drop the injection guard so the next context re-injects |
| `require-log.sh` | at every turn end: no session log today? remind (`warn`), block (`strict`), or nothing (`off`) |
| `learn-nag.sh` | at every turn end: two corrections this session and no feedback memory since the first? say so once |
| `close-log.sh` | on `/clear`: stamp the boundary into today's latest log |
| `rebuild-index-hook.sh` | at session end: regenerate both indexes, detached so the exit is never blocked |

Every command resolves through `${CLAUDE_CONFIG_DIR:-$HOME/.claude}`, so the same wiring works in a
default install and in an isolated sandbox. On the recommended route the hooks live in a small
generated plugin at `<config>/skills/raememberit/`, and `settings.json` carries none of them.
